# Final Spec Template

Use this when no native spec system exists, or as a checklist for native artifacts.

```markdown
# <Feature/Bug/Change Name>

## Problem

## Goals

## Non-Goals

## Users / Jobs To Be Done

## Research Summary

## Chosen Approach

## Decision Log / Rationale

## Rejected Alternatives

## UX / User Flow

## Requirements

## Edge Cases and States

## Data / API / System Design

## Implementation Notes

## Acceptance Criteria

## Test Plan

## Metrics / Rollout

## Risks and Mitigations

## Open Questions

## Tasks
```

## Bug Additions

For bugs, also include:

```markdown
## Expected vs Actual

## Reproduction Steps

## Impact and Severity

## Root Cause Hypotheses

## Fix Requirements

## Regression Tests
```

## Quality Bar

The final spec is not done until:

- problem and goal are clear
- non-goals are explicit
- requirements are testable
- UX states are covered when user-facing
- implementation notes reflect codebase research
- acceptance criteria are specific
- test plan is actionable
- decision rationale and rejected alternatives are captured
- open questions are visible
- tasks can be executed by a coding agent
```
