# Research Options

Use this when product, UX, market, API, library, competitor, or implementation facts matter.

## Research Principle

Research the user's goal, not just the proposed solution.

## Web-First Rule

Use web search to discover sources, then web fetch/extract or browser inspection to read the strongest primary sources. Do not stop at search snippets when precise product, API, policy, or implementation details matter.

## Sources to Prefer

Prefer primary and durable sources:

- official product docs
- help centers
- changelogs
- API docs
- standards/specifications
- public product pages
- reputable engineering/design writing
- app store/user reviews only when user sentiment matters

Use live web research for current products, APIs, libraries, pricing, policies, competitors, legal constraints, market facts, standards, UX examples, and implementation approaches. If web tools exist and the user has not forbidden browsing, live research is mandatory for these categories.

## Questions to Answer

- How do comparable products solve this?
- What user expectations already exist?
- What UX conventions are standard?
- What are common complaints or failure modes?
- What should we copy because it is familiar?
- What should we avoid because it adds friction, dark patterns, or complexity?
- What can be novel or differentiated in this product/system?

## Research Anti-Patterns

Avoid:

- raw source dumps
- generic “best practices” with no product implication
- recommending before comparing options
- using stale memory for current facts
- overfitting to one competitor
